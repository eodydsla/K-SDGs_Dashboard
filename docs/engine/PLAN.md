# K-SDGs 환경분야 지표 대시보드 — 설계 기록

> 실행 방법·화면 구성·CSV 형식은 [README.md](./README.md)와 [sheets/README.md](./sheets/README.md)를 보세요.
> 이 문서는 **왜 이렇게 만들었는지**를 남겨둔 기록입니다.

## 1. 배경

EU JRC의 두 대시보드를 참고 모델로 삼았다.

- **[EU BDS Actions Tracker](https://dopa.jrc.ec.europa.eu/kcbd/actions-tracker/)** — 이행과제를 상태(완료/추진중/지연)·기한별로 추적. 상단 상태별 집계 카드, 주제별 그룹 아코디언, 상태·연도 칩, 요약문 + 근거 링크.
- **[EU BDS 2030 Dashboard](https://dopa.jrc.ec.europa.eu/kcbd/EUBDS2030-dashboard/)** — 타깃별 지표의 목표 대비 진척도. 기준값·목표값·최신값·달성률·시계열 차트·메타데이터(출처·산출방법·갱신주기).

이 둘을 **한 앱에 합쳤다**(지표 대시보드 + 이행과제 트래커). 자체 환경계획 지표가 아직 확정되지 않아
우선 **K-SDGs 환경 3개 목표(13·14·15)** 로 샘플을 구축했고, 계획지표가 나오면 내용만 교체한다.

## 2. 아키텍처 결정 기록

### 구글 스프레드시트 연동 → Next.js + DB + 관리자 페이지로 변경

처음에는 데이터량이 적고 팀원 몇 명이 수정한다는 점 때문에 **구글시트를 단일 원천으로 두고 CSV를 직접
fetch**하는 무백엔드 구성을 계획했다. 실제로 시트 탭 6개 구조와 시드 CSV까지 만들었다.

그런데 탭 6개를 사람이 직접 관리하는 방식이 **오히려 번거롭고 실수하기 쉽다**는 판단이 있었다.
(어느 탭에 무엇을 넣는지 헷갈림, 컬럼 규칙 위반, 시트를 공개해야 하는 제약)

→ **Next.js + SQLite + 관리자 CRUD**로 전환했다. 대신 이미 만든 CSV는 버리지 않고
**초기 시드 데이터 + CSV 가져오기 형식의 견본**으로 계속 쓴다. 엑셀로 대량 작업하고 싶을 때는
`/admin/data`에서 붙여넣기·업로드하면 되므로, 시트 방식의 장점(대량 편집)도 그대로 남아 있다.

### 그 밖의 선택

| 항목 | 선택 | 이유 |
|---|---|---|
| DB | SQLite (Prisma) | 로컬·사내서버 운영 전제. 파일 하나면 끝, 계정·설정 불필요. Postgres 전환도 Prisma라 변경 적음 |
| 인증 | 공용 비밀번호 + HMAC 서명 쿠키 | 팀 규모가 작아 계정 관리 비용이 이득보다 큼. 대신 모든 변경을 `AuditLog`에 남겨 추적성 확보 |
| UI | shadcn/ui + Tailwind v4 | 컴포넌트를 소스로 들고 있어 커스터마이즈 자유로움 |
| 쓰기 경로 | 서버 액션 | 별도 API 레이어 없이 폼 → DB. 각 액션이 `requireAdmin()` + 감사로그를 일관되게 수행 |

## 3. 핵심 설계 원칙

### 프레임워크 중립 — 코드에 K-SDGs를 하드코딩하지 않는다

목표 개수, 지표 개수, `13`/`14`/`15` 같은 값이 코드 어디에도 없다. 계층 명칭조차 `config` 테이블에서
주입한다. 덕분에 **자체 환경계획 지표로의 전환이 "관리자에서 내용 갈아끼우기"로 끝난다.**

- 목표를 4번째로 추가 → 카드·필터·집계가 자동으로 늘어나고, 색은 팔레트에서 자동 배정
- `level1_label`을 「부문」으로 바꾸면 공개·관리자 화면의 용어가 한 번에 바뀜

### 기대진행률은 "최신 데이터 연도" 기준

처음 설계에서는 현재연도 기준으로 잡았는데, 검증 중에 문제를 발견해 바꿨다.
통계 공표가 1~2년 늦는 지표(2026년에 2024년 실적)를 현재연도 기대치와 비교하면 **정상적으로 진행 중인
지표까지 전부 「지연」으로 찍힌다.** 지금은 최신 데이터 연도 시점의 기대치와 비교한다.

실제로 이 수정 하나로 샘플 13개 지표의 판정이 「지연 10건」에서 「순조 5 / 지연 5 / 달성 1 / 악화 1 / 모니터링 1」로 바뀌었다.

### 색은 두 층으로 분리

「전부 같은 색이라 밋밋하다」를 피하기 위해:

- **목표색(다양성)** — 색 하나만 지정하면 HSL로 분해해 배경 tint·보더·텍스트·그라디언트 끝색·반투명
  오버레이가 자동 파생되고, 헤더 그라디언트 / 도넛 / 차트 / 카드 좌측 액센트 바 / 필터 칩에 전파된다.
  목표 섹션마다 화면 인상이 확 달라진다.
- **상태색(일관성)** — 달성/순조/지연/악화/모니터링/자료없음은 전 화면 동일. 색맹 대비로 아이콘·텍스트 병기.

### 임시저장(비공개) 상태

목표·세부목표·지표·이행과제 모두 `published` 플래그를 가진다. 작성 중인 항목을 공개 화면에서 감추되
데이터는 보존하고, `/admin/preview`에서 임시저장 항목까지 포함해 실제 화면으로 확인할 수 있다.

## 4. 검증 결과

빌드(`npm run build`)와 타입체크 통과. 실행 중인 서버에 대해 폼 제출을 그대로 재현하는 방식으로
20개 항목을 확인했고 전부 통과했다.

- 로그인: 틀린 비밀번호 거부(쿠키 미발급) / 올바른 비밀번호 httpOnly 세션 발급
- 비로그인 `/admin` 접근 → `/login` 리다이렉트
- 실적값 추가 → DB 반영 → 최신값·달성률 재계산
- 목표를 색 없이 4번째로 추가 → 공개 개요에 카드 자동 추가(코드 수정 0), 색 자동 배정
- 지표 임시저장 전환 → 공개 화면에서 사라지고 미리보기에는 배지와 함께 표시
- 탭 구분 표 붙여넣기 → 실적값 2건 일괄 반영
- 계층 명칭을 「부문/추진전략/계획지표」로 변경 → 공개 화면 용어 일괄 변경 (**계획지표 전환 리허설**)
- 공개 4개 화면 + 관리자 10개 화면 렌더, CSV 내보내기 응답

검증 후 DB는 시드 상태로 되돌려 놓았다.

## 5. 남은 일 · 알아둘 점

- **수치는 형식 예시다.** 대외 공개 전 소관 부서 검수·교체 필요.
- 배포 전 `.env`의 `ADMIN_PASSWORD`·`SESSION_SECRET` 교체 필수.
- Node 18 대응으로 `@tailwindcss/oxide-linux-x64-gnu`를 `dependencies`에 고정해 두었다.
  Node 20 이상 또는 Linux x64가 아닌 환경에서는 이 줄을 지울 것.
- 계정별 로그인, 지역(시도)별 지표 분해, 이행과제↔지표 연결 강화는 필요해지면 추가.
  (`IndicatorValue.region` 컬럼은 시도별 확장을 미리 염두에 두고 넣어둔 것)
