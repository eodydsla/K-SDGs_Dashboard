## 1. 배경

### 1.1 문제

환경계획의 이행 상황은 보통 연 1회 한글/엑셀 보고서로 정리된다. 이 방식은 세 가지 문제가 있다.

- **열람성** — 지표의 기준값·목표값·최신값·달성률이 문서 안에 흩어져 있어, 지금 무엇이 지연되고 있는지 한눈에 안 보인다.
- **갱신성** — 통계가 갱신돼도 문서를 다시 만들어야 반영된다.
- **추적성** — 누가 언제 어떤 수치를 고쳤는지 남지 않는다.

### 1.2 참고 모델

EU JRC(Joint Research Centre)의 두 대시보드를 참고 모델로 삼고, **두 개를 한 앱에 합친다.**

| 참고 사이트 | 가져온 요소 |
|---|---|
| [EU BDS Actions Tracker](https://dopa.jrc.ec.europa.eu/kcbd/actions-tracker/) | 상단 상태별 집계 카드, 주제별 그룹 아코디언, 상태·기한 칩, 요약문 + 근거 링크 |
| [EU BDS 2030 Dashboard](https://dopa.jrc.ec.europa.eu/kcbd/EUBDS2030-dashboard/) | 지표별 기준값·목표값·최신값·달성률, 시계열 차트, 메타데이터(출처·산출방법·갱신주기) |

### 1.3 왜 지금 K-SDGs 데이터인가

최종 목표는 **자체 환경계획 지표** 대시보드지만 계획지표가 아직 확정되지 않았다.
그래서 **K-SDGs 환경분야(13 기후변화·14 해양생태계·15 육상생태계)** 로 먼저 샘플을 구축하고,
계획지표가 확정되면 **코드 수정 없이 관리자 화면에서 내용만 교체**해 전환한다.

이 전환 요건이 제품의 최우선 제약이며, 3장에서 별도로 정의한다.

## 3. 최우선 제약 — 프레임워크 중립성

**코드에 K-SDGs를 하드코딩하지 않는다.**

### 3.1 금지 사항

- 영역·목표·세부목표·지표의 **개수를 상수로 두는 것**
- `13`, `G13`, `"plan"`, `"state"` 같은 **개별 값이 로직·컴포넌트에 등장하는 것**
- "모니터링 영역", "목표", "세부목표", "지표"라는 **단어를 화면에 직접 쓰는 것**

### 3.2 구현 규칙

| 규칙 | 구현 |
|---|---|
| 계층 명칭은 데이터에서 주입 | `Config`의 `level0_label`~`level3_label` → `getConfig()` |
| 영역 코드는 DB 값이자 URL | `Track.code` → `[track]` 동적 세그먼트, 메뉴도 `Track` 목록에서 생성 |
| 개수 무관 레이아웃 | `grid-cols-[repeat(auto-fit,minmax(NNNpx,1fr))]` |
| 색 자동 배정 | `goalColor(color, index)` — 미지정 시 10색 팔레트에서 순서대로 |
| 연도 범위 | 데이터의 min/max에서 도출 |
| 정렬 | `order` 우선, 없으면 `code` 자연정렬 (중간 삽입해도 순서 유지) |

### 3.3 수용 기준

- 설정에서 `level1_label`을 「부문」으로 바꾸면 공개·관리자 전 화면의 "목표"가 "부문"으로 바뀐다.
- 목표를 4번째로 추가하면 개요에 카드가 **코드 수정 없이** 하나 더 생기고, 색이 자동 배정된다.
- 영역을 추가하면 상단 메뉴와 `/{코드}` 주소가 자동 생성된다.

> 기능을 추가할 때마다 **"목표가 4개, 6개로 늘어도 그대로 동작하는가"** 를 확인한다.

## 5. 핵심 규칙 — 달성도 계산

`src/lib/progress.ts` **한 곳에서만** 관리한다. 규칙 변경은 이 파일에서만 이루어져야 한다.

### 5.1 계산식

```
진행률(%)     = (최신값 − 기준값) ÷ (목표값 − 기준값) × 100
기대진행률(%) = (최신 데이터 연도 − 기준연도) ÷ (목표연도 − 기준연도) × 100
```

- **분모의 부호가 증감 방향을 자동 흡수**한다. 온실가스 배출량처럼 작아져야 좋은 지표도 같은 식으로 계산된다.
  → `direction`(up/down)은 **계산에 쓰지 않고**, 추세 화살표 색과 안내 문구에만 쓴다.
- 표시용 진행률은 0~100으로 클램프하고, 판정용 원본값(`rawProgress`, 음수 가능)은 따로 보관한다.
- 기대진행률은 0~100으로 클램프한다.

### 5.2 기대진행률의 기준 시점 — 변경 금지 규칙

**현재연도가 아니라 「최신 데이터 연도」 기준이다.**

통계 공표가 1~2년 늦는 지표(2026년에 2024년 실적)를 현재연도 기대치와 비교하면
**정상적으로 진행 중인 지표까지 전부 「지연」으로 찍힌다.**
실제로 이 한 줄 차이로 샘플 13개 지표의 판정이 「지연 10건」에서
「순조 5 / 지연 5 / 달성 1 / 악화 1 / 모니터링 1」로 바뀌었다.

### 5.3 상태 판정 6종

| 상태 | 조건 | 색 |
|---|---|---|
| 달성 | 진행률 ≥ 100% | `#2B8A3E` |
| 순조 | 진행률 ≥ 기대진행률 × 0.9 | `#1971C2` |
| 지연 | 0 ≤ 진행률 < 기대진행률 × 0.9 | `#E8590C` |
| 악화 | 진행률 < 0 (기준값보다 후퇴) | `#C92A2A` |
| 모니터링 | 목표값 미설정 | `#868E96` |
| 자료없음 | 실적값 없음 | `#ADB5BD` |

- 기대진행률을 구할 수 없으면(기준연도·목표연도 미설정) 진행률 50%를 기준으로 순조/지연을 나눈다.
- `statusOverride`가 유효한 상태값이면 자동 판정 대신 그것을 쓴다.
- 최신 데이터가 **3년(`STALE_YEARS`) 넘게** 갱신되지 않으면 「자료 갱신 필요」 배지를 병기한다.
  (상태 판정 자체는 바꾸지 않는다.)
- 접근성을 위해 상태 배지는 색만으로 구분하지 않고 **아이콘·텍스트를 병기**한다.

### 5.4 파생 값

- **추세** — 직전 연도 대비 변화량. `direction`을 반영해 개선(good)/악화(bad)/변화없음(flat)으로 색을 정한다.
- **평균 달성도** — 소속 지표 진행률의 평균 (자료없음·모니터링 제외).
- **숫자 표기** — 1000 이상 소수점 없음, 100 이상 1자리, 그 외 2자리. 천단위 콤마, `tabular-nums`.
- **값 없음과 0의 구분** — 값 없음은 빈 칸으로 둔다. `0`은 "실제로 0"이라는 뜻이다.

## 6. 기능 요구사항

### 6.1 공통 레이아웃

- **화면 전체 폭 사용.** 최대폭 제한 없이 좌우 여백만 준다.
- 유동 개수 그리드는 `auto-fit`: 목표 카드 `minmax(340px,1fr)` / 지표 카드 `minmax(330px,1fr)` / 집계 카드 `minmax(210px,1fr)`
- 헤더 최상단에 **목표색이 가로로 흐르는 얇은 띠** (개수 무관 균등 분할).
- 헤더(sticky): 사이트명 + 부제 + 영역 네비게이션 + 최종 갱신일 + 관리자 버튼.
- 모바일 1열, 넓은 표는 가로 스크롤 컨테이너 안에.

### 6.2 `/` — 통합 현황

전체 영역을 한 화면에서 비교한다.

1. **히어로** — 사이트 제목·부제 + 전체 평균 달성도 + 전체 지표 수, 상단 영역색 띠
2. **전체 상태별 집계 카드**
3. **영역 카드**(영역당 1장) — 영역색 그라디언트 헤더 + 아이콘 + 도넛 평균 달성도 + 목표/지표/이행과제 수
   + 상태 스택바 + 소속 목표 목록. 클릭 시 `/{track}`으로 이동
4. **전 영역에서 관리가 필요한 지표** 8개 — 클릭 시 해당 영역의 지표 상세로 이동

### 6.3 `/{track}` — 영역 개요

1. **히어로** — 목표색 띠 + 프레임워크명 + 제목·부제 + 평균 달성도 + "지표 전체 보기" 버튼
2. **상태별 집계 카드** — 전체 지표 수(진한 카드) + 상태별 개수·비율·미니 바
3. **목표 카드**(목표당 1장) — 그라디언트 헤더 + 큰 이모지 + 번호·이름·설명 + 도넛 평균 달성도
   + 지표/세부목표 수 + 상태 스택바·범례 + 대표지표(`isHeadline`) 최대 2개.
   **클릭 시 해당 목표로 필터된 지표 화면으로 이동**
4. **관리가 필요한 지표**(지연·악화, 진행률 낮은 순 5개) / **목표에 근접한 지표**(높은 순 5개)
   — **클릭 시 `?indicator=<id>`로 이동해 상세가 바로 열려야 한다**
5. **이행과제 요약** — 완료/추진중/지연/예정 카운트 (이행과제가 있는 영역만)

### 6.4 `/{track}/indicators` — 지표

**필터 바**: 목표 칩(각 지표 수 표시, 활성 시 목표색 배경) / 상태 칩(0건이면 숨김) /
검색어(지표명·설명·세부목표·담당·출처) / 정렬(지표번호·달성도 높은순·낮은순·최신 자료순) /
카드↔목록 전환 / 필터 초기화

**카드 그리드** — 세부목표별로 그룹핑, 그룹 헤더에 목표색 세로선 + 코드 + 이름 + 지표 수

**지표 카드 1장**
- 좌측 4px 목표색 액센트 바 + 아주 옅은 목표색 tint 배경
- 지표번호 배지 + 목표명 + 상태 배지 (+ 임시저장 배지)
- **최신값을 크게** + 단위 + 최신연도 + 전년 대비 증감 화살표 + 비고 + 「자료 갱신 필요」 배지
- 미니 스파크라인(목표색 그라디언트 area)
- 진행률 바(목표색 그라디언트 + **기대진행률 위치 눈금**) + 기준값 → 달성% → 목표값
- 목표값이 없으면 진행률 바 대신 「모니터링 지표」 안내

**목록 보기** — 지표 / 최신값 / 기준 / 목표 / 달성도 / 상태 표

**상세 드로어**(우측 Sheet, 카드·행 클릭 시)
- 상단 목표색 띠, 지표번호·계층 경로·상태
- 최신값 + 목표 대비 달성도 + 진행률 바 + 기대진행률 + 상태 설명
- **시계열 차트** — 기준선(회색 점선) · 목표선(녹색 점선), 목표연도가 데이터보다 뒤면 X축을 목표연도까지 확장
- 지표 설명 / 산출식 / 단위 / 방향 / 출처(+링크) / 갱신주기 / 담당 / 비고
- 원자료 표(최신 연도 먼저) + **해당 지표 CSV 내려받기**(UTF-8 BOM)

**딥링크**: `?goal=<id>` 해당 목표로 필터 진입 / `?indicator=<id>` 상세 드로어가 열린 상태로 진입

### 6.5 `/{track}/actions` — 이행과제

**이행과제가 0건인 영역은 하위 메뉴에서 탭 자체가 빠진다**(관측·조사만 하는 영역).
직접 주소로 들어오면 "등록된 이행과제가 없습니다" 안내.

- 상태별 집계 카드 4개 (클릭 시 그 상태로 필터, 활성 시 링 표시)
- 필터: 목표 / 기한 연도 / 검색어 / 초기화
- 목표별 그룹 → 아코디언
  - 접힘: 과제번호 + 상태 칩 + 기한 칩 + 세부목표 코드 + 과제명 + 요약 1줄
  - 펼침: 추진 경과 전문 + 담당 기관 + 최종 수정일 + 근거 링크 버튼

### 6.6 `/{track}/data` — 데이터·방법론

- 달성도 계산식 2개와 설명 (특히 "최신 데이터 연도 기준"인 이유)
- 상태 6종 판정 조건 표
- 전체 지표 메타데이터 표 (번호·지표명·정의·단위·기준·최신·목표·출처·갱신주기·담당·상태)
- 전체 CSV 내려받기

## 7. 색상 시스템

"전부 같은 색이라 밋밋하다"를 피하기 위해 **두 층으로 분리**한다.

### 7.1 목표색 — 다양성 담당

- 색 **하나만** 지정하면 HSL로 분해해 자동 파생:
  `tint`(L 96.5%, 배경) / `border`(L 87%) / `text`(L 30%) / `deep`(L 32%, 그라디언트 끝) / 투명도 3단계(`a08`·`a15`·`a30`)
- 이 색이 **헤더 그라디언트 / 카드 좌측 액센트 바 / 도넛 링 / 차트 라인·area / 아이콘 배경 / 활성 필터 칩 / 진행률 바**에 전파된다.
- **색을 비우면** 10색 팔레트에서 순서대로 자동 배정 → 항목이 늘어도 색이 겹치거나 비지 않는다.
  `#E8590C #0B7285 #2F9E44 #5F3DC4 #0B5394 #B02A37 #7048E8 #087F5B #D6336C #A9761A`

**제약**: 색 톤 객체(`Tones`)는 **전부 문자열이어야 한다.** 함수를 넣으면 서버 → 클라이언트 컴포넌트로 props 전달이 불가능해진다.

### 7.2 상태색 — 일관성 담당

5.3의 6색을 전 화면에서 **동일한 의미로만** 쓴다. **절대 변주하지 않는다.**

### 7.3 밋밋함을 깨는 장치

목표 카드 그라디언트 헤더 + 큰 이모지 + 도넛 링 / 지표 카드 좌측 액센트 바 + 옅은 tint + 큰 숫자 /
차트·스파크라인의 그라디언트 area fill / 진행률 바의 그라디언트 + 기대진행률 눈금 / 카드 hover 시 그림자·이동.

## 8. 데이터 입출력 — CSV 왕복

- 대상 7종: `tracks` / `goals` / `targets` / `indicators` / `values` / `actions` / `config`
- **내려받은 CSV를 그대로 다시 올릴 수 있어야 한다.** 내보내기 스키마(`CSV_HEADERS`)와 가져오기가
  같은 컬럼명을 쓰므로 **한쪽만 바꾸면 왕복이 깨진다.**
- 엑셀 한글 깨짐 방지를 위해 내보낼 때 **UTF-8 BOM**을 붙인다.
- 올리기는 **파일 업로드**와 **표 붙여넣기** 둘 다 지원, 붙여넣기는 **탭 구분(TSV) 자동 감지**.
- 첫 줄은 헤더. **컬럼 순서는 달라도 되고**(이름으로 탐색), 모르는 컬럼은 무시한다.
- 고유번호(`track_id`/`goal_id`/`target_id`/`indicator_id`/`action_id`) 기준 **upsert**.
- "기존 데이터를 모두 지우고 넣기" 옵션은 두되, 체크 시 **경고 배너**와 백업 권고를 띄운다.
- **행 단위 실패가 전체를 중단시키지 않는다.** 몇 행에서 왜 실패했는지 메시지에 담는다.
  예: `3건 추가, 2건 수정, 1건 건너뜀 — 5행: 상위 목표 G99 를 찾을 수 없음`
- 처음부터 전체를 넣을 때의 순서를 화면에 안내: **영역 → 목표 → 세부목표 → 지표 → 실적값 → 이행과제 → 설정**
- 공개 화면의 영역별 내려받기를 위해 `?track=<코드>` 필터를 지원한다.

## 9. 인증 · 권한

- 공용 비밀번호 1개 (`.env`의 `ADMIN_PASSWORD`). 계정 개념이 없으므로 추적성은 AuditLog가 담당한다.
- 세션은 **HMAC-SHA256 서명 쿠키** — `httpOnly`, `sameSite=lax`, 운영에서 `secure`, **12시간** 만료.
- 비밀번호·서명 비교는 **타이밍 안전 비교**(`timingSafeEqual`).
- 비로그인 `/admin/*` 접근 → `/login` 리다이렉트.
- **모든 쓰기 서버 액션은 첫 줄에서 `requireAdmin()`을 호출한다.** 화면 보호(layout 가드)만으로는 부족하다.
- 로그아웃 → 쿠키 삭제 후 `/`로 이동.

### 9.1 쓰기 경로 규약

모든 변경은 서버 액션(`src/lib/admin-actions.ts`)을 거치며, 새 액션도 이 순서를 지킨다.

1. `await requireAdmin()`
2. 작업 수행
3. `await log(action, entity, id, label, detail)` — **AuditLog 필수**
4. `refresh()` (= `revalidatePath("/", "layout")`)
5. `return { ok, message }`, 예외는 `fail(e)`로 감싸 사람이 읽을 메시지로 변환

## 10. 비기능 요구사항

### 10.1 성능

- 공개 화면 TTFB 100ms 이내 (SQLite + 인메모리 계산).
- **운영 배포는 반드시 `npm run build && npm start`.** dev 모드는 JS를 압축 없이 내보내
  청크 하나가 7MB를 넘고, 이것이 체감 느림의 대부분이다.
- **차트 라이브러리(Recharts)는 지연 로딩** (`next/dynamic`, `ssr: false`) → 지표 화면 259KB → 147KB.
  직접 `trend-chart`를 import하면 첫 로딩 번들이 100KB 이상 커진다.
- **웹폰트 굵기는 실제로 쓰는 것만.** 한글 폰트는 굵기 하나당 유니코드 서브셋 파일이 124개 생긴다.
  Noto Sans KR 400/500/700만 사용, `display: swap`.

### 10.2 확장성

- 목표·세부목표·지표·연도·이행과제를 추가해도 **코드 수정 없이** 화면이 늘어난다.
- 목표가 6~8개로 늘어도 auto-fit 그리드로 레이아웃이 버틴다.

### 10.3 데이터 안전

- 삭제는 확인 후 실행하고, 하위 항목 개수를 미리 알린다 (FK는 Cascade, 이행과제는 SetNull).
- 시드 스크립트는 **기존 데이터를 모두 지우고** 다시 채운다 — 문서에 명시한다.
- **실적값 없음과 0을 구분한다.** 빈 칸으로 두고 0을 넣지 않는다.

### 10.4 접근성

- 상태는 색만으로 구분하지 않고 아이콘·텍스트를 병기한다.
- 진행률 바에 `role="progressbar"`와 aria 속성.
- 아이콘 전용 버튼에 `aria-label` 또는 `sr-only` 텍스트.

### 11.1 데이터 흐름

```
Prisma (SQLite)
  └ lib/data.ts  getDashboard(includeUnpublished)
      ├ Track ⊃ Goal ⊃ Target ⊃ Indicator ⊃ IndicatorValue 를 한 번에 조회
      ├ 각 Indicator 에 compute() 결과를 부착 (lib/progress.ts)
      ├ 목표색·톤을 지표까지 평탄화해 전달 (color, tone, goalName, targetCode …)
      ├ 이행과제는 goal→track 을 되짚어 각 Track.actions 에 배분
      └ DashTrack / DashGoal / DashIndicator / DashAction / config 반환
  └ findTrack(dashboard, code) 로 URL 영역 코드 해석 (없으면 notFound())
  └ 서버 컴포넌트 → 클라이언트 컴포넌트 props
```

- `getDashboard(true)`는 임시저장 항목까지 포함한다. 관리자 화면과 `/admin/preview`만 `true`를 쓰고, 공개 화면은 기본값(`false`).
- `DashIndicator`는 상위 계층 정보를 **평탄화해서** 들고 있다 — 필터·카드에서 매번 조인을 되짚지 않기 위한 의도이므로 유지한다.
- 모든 페이지가 `export const dynamic = "force-dynamic"` (매 요청 DB 조회).

### 11.2 명령

```bash
npm run dev                 # 개발 서버 (PORT=8006 npm run dev 로 포트 지정)
npm run build && npm start  # 운영 빌드·실행
npm run lint / npx tsc --noEmit
npm run db:push             # schema.prisma → SQLite 반영
npm run db:seed             # sheets/*.csv → DB (기존 데이터 전부 삭제 후 재주입)
npm run db:studio
```

### 11.3 환경변수

```
DATABASE_URL="file:./dev.db"
ADMIN_PASSWORD="..."        # 배포 전 반드시 변경
SESSION_SECRET="..."        # openssl rand -hex 32
```

`.env`는 커밋하지 않고 `.env.example`만 커밋한다.

### 11.4 운영 환경 제약

- **Node 20+ 권장.** Node 18에서는 Tailwind v4 네이티브 모듈(`@tailwindcss/oxide`)이 engines 불일치로
  조용히 건너뛰어져 `Cannot find native binding` 빌드 실패 → `npm run fix:node18` 1회 실행.
- 플랫폼 전용 패키지는 반드시 `optionalDependencies`에 둔다 (`dependencies`에 넣으면 다른 OS에서 `npm install` 자체가 실패).
- **dev 서버를 켜둔 채 `npm run build` 금지** — 둘 다 `.next`를 쓰므로 실행 중 dev 서버가 깨진다. 깨졌으면 `rm -rf .next`.

## 12. 수용 기준

자동화된 테스트 스위트는 없다. 서버를 띄운 뒤 렌더된 HTML에서 `<form>`의 `$ACTION_*` 히든 필드를
추출해 그대로 재전송하는 방식으로 검증한다. (서버 액션은 `useActionState` 시그니처 `(prevState, formData)`라
히든 필드 없이 POST하면 `fd.get is not a function`이 난다.)

**아래 26개 항목이 모두 통과해야 완료로 본다.**

### 인증
1. 비로그인 `/admin` 접근 → `/login` 리다이렉트 (307)
2. 틀린 비밀번호 → 거부, 세션 쿠키 미발급
3. 올바른 비밀번호 → `httpOnly` 세션 쿠키 발급, `/admin` 200
4. 로그아웃 → 303, `Location: /`, 세션 쿠키 만료

### 데이터 편집
5. 실적값 추가 → DB 반영
6. 최신값·달성률이 재계산됨
7. 실적값 추가 후 공개 지표 화면 정상 응답

### 확장성
8. 목표를 4번째로 추가 → DB 생성
9. 색 미지정 시 `color`가 비어 자동 배정 대상이 됨
10. 공개 개요에 새 목표 카드가 **코드 수정 없이** 노출
11. 목표 카드 개수가 자동으로 늘어남

### 임시저장
12. 지표 공개 토글 → `published=false`
13. 공개 대시보드에서 사라짐
14. 관리자 미리보기에는 보임
15. 미리보기에 「임시저장」 배지 표시

### CSV
16. 탭 구분 표 붙여넣기로 실적값 2건 일괄 반영

### 계획지표 전환 리허설
17. 설정에서 계층 명칭을 「부문/추진전략/계획지표」로 변경
18. 공개 개요 문구가 "부문별 현황"으로 바뀜
19. 지표 화면 제목이 "계획지표 현황"으로 바뀜

### 모니터링 영역
20. 통합 화면에 영역 3개 카드와 각 영역 링크 노출
21. 각 영역 화면에는 **자기 영역 지표만** 보인다
22. 이행과제가 0건인 영역은 하위 메뉴에서 이행과제 탭이 빠진다
23. 이행과제가 있는 영역은 탭이 노출된다
24. 존재하지 않는 영역 주소는 404
25. `?track=<코드>` CSV 내보내기가 해당 영역 지표만 담는다

### 화면
26. 공개 화면(통합 1 + 영역 3 × 4) + 관리자 10개 화면 모두 200, CSV 내보내기 동작

### 추가 수동 확인
- 개요의 「관리가 필요한 지표」 클릭 → 해당 지표 상세 드로어가 열린 채로 이동
- 목표 카드 클릭 → 해당 목표로 필터된 지표 화면
- 넓은 화면에서 카드가 좌우 여백 없이 꽉 차고 빈 열이 생기지 않음
- 브라우저 콘솔에 Base UI 경고 없음

> 검증 시 유의: Base UI 다이얼로그는 포털이라 서버 HTML에 드로어 내용이 없다(하이드레이션 직후 열리는 것이 정상).
> React SSR 텍스트 보간은 `부문<!-- -->별 현황`처럼 주석이 끼므로 HTML 문자열 검사 전 제거해야 한다.
