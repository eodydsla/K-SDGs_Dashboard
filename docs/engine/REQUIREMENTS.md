## 1. 배경과 목적

### 1.1 참고 모델

EU JRC(Joint Research Centre)의 두 대시보드를 참고 모델로 삼는다.

| 참고 사이트 | URL | 가져올 요소 |
|---|---|---|
| EU BDS Actions Tracker | https://dopa.jrc.ec.europa.eu/kcbd/actions-tracker/ | 상단 상태별 집계 카드, 주제별 그룹 아코디언, 상태·기한 칩, 요약문 + 근거 링크 |
| EU BDS 2030 Dashboard | https://dopa.jrc.ec.europa.eu/kcbd/EUBDS2030-dashboard/ | 지표별 기준값·목표값·최신값·달성률, 시계열 차트, 메타데이터(출처·산출방법·갱신주기) |

**두 개를 한 앱에 합친다.** 지표 대시보드 + 이행과제 트래커를 탭으로 나란히 둔다.

### 1.2 왜 K-SDGs인가

최종 목표는 **자체 환경계획 지표** 대시보드지만, 계획지표가 아직 확정되지 않았다.
그래서 우선 **K-SDGs(국가 지속가능발전목표)의 환경 분야 3개 목표**로 샘플을 구축하고,
나중에 계획지표가 나오면 **코드 수정 없이 내용만 교체**해서 전환한다.

이것이 이 프로젝트의 **가장 중요한 제약**이다. 아래 3장(프레임워크 중립성)에서 상세히 다룬다.

### 1.3 사용자

- **일반 열람자** — 로그인 없이 공개 대시보드를 본다.
- **팀원 몇 명** — 관리자 비밀번호를 공유하고 지표·실적값·이행과제를 직접 수정한다.
  개발 지식이 없다는 전제로, 화면에서 모든 것을 편집할 수 있어야 한다.

## 3. 핵심 설계 원칙 — 프레임워크 중립성 (최우선)

**코드에 K-SDGs를 하드코딩하지 않는다.**

금지 사항:
- 영역 개수, 목표 개수, 지표 개수를 코드에 상수로 두는 것
- `13`, `14`, `15`, `G13`, `"plan"`, `"state"` 같은 값이 컴포넌트나 로직에 등장하는 것
- "모니터링 영역", "목표", "세부목표", "지표"라는 **단어조차** 화면에 하드코딩하는 것

구현 방식:
- 계층 명칭은 `Config` 테이블의 `level0_label` ~ `level3_label`에서 주입한다.
- **영역 코드는 URL 세그먼트이자 DB 값이다.** 라우팅은 `[track]` 동적 세그먼트를 쓰고,
  메뉴는 `Track` 목록에서 생성한다. 코드 어디에도 `plan`/`state`/`perception`이 등장하면 안 된다.
- 목표 색은 지정 안 하면 팔레트에서 순서대로 자동 배정한다.
- 그리드는 고정 열 수가 아니라 `auto-fit`으로, 항목이 몇 개든 한 줄을 채운다.
- 연도 범위는 코드가 아니라 데이터의 min/max에서 도출한다.
- 정렬은 `order` 컬럼 우선, 없으면 코드 자연정렬 → 중간에 끼워 넣어도 순서가 안 깨진다.

**검증 방법**: 관리자에서 `level1_label`을 "부문"으로 바꾸면 공개·관리자 화면의 모든 "목표"가
"부문"으로 바뀌어야 한다. 목표를 4번째로 추가하면 개요에 카드가 자동으로 하나 더 생겨야 한다.

> 이 원칙 덕분에 **자체 환경계획 지표로의 전환이 "관리자에서 내용 갈아끼우기"로 끝난다.**

## 4. 데이터 모델

**모든 쓰기 작업은 반드시 AuditLog를 남긴다.** 공용 비밀번호라 개인 식별이 안 되는 대신,
무엇이 언제 바뀌었는지는 추적 가능해야 한다.

## 5. 달성도 계산 규칙 (`src/lib/progress.ts`)

이 규칙이 대시보드 전체의 핵심이며, **한 파일에서만 관리한다.**

### 5.1 진행률

```
진행률(%) = (최신값 − 기준값) ÷ (목표값 − 기준값) × 100
```

- 분모의 부호가 증가·감소 방향을 **자동으로 흡수**한다. 따라서 온실가스 배출량처럼
  값이 작아져야 좋은 지표도 **같은 식**으로 계산된다. `direction`은 계산에 쓰지 않는다.
- 표시용은 0~100으로 클램프하되, 판정용 원본값(음수 가능)은 따로 보관한다.

### 5.2 기대진행률 — ⚠️ 이 부분이 중요

```
기대진행률(%) = (최신 데이터 연도 − 기준연도) ÷ (목표연도 − 기준연도) × 100
```

**현재연도가 아니라 "최신 데이터 연도" 기준이다.**

이유: 통계 공표가 1~2년 늦는 지표(2026년에 2024년 실적)를 현재연도 기대치와 비교하면
**정상적으로 진행 중인 지표까지 전부 「지연」으로 찍힌다.**
실제로 이 한 줄 차이로 샘플 13개 지표 판정이 「지연 10건」에서
「순조 5 / 지연 5 / 달성 1 / 악화 1 / 모니터링 1」로 바뀌었다.

### 5.3 상태 판정

| 상태 | 조건 | 색 |
|---|---|---|
| 달성 | 진행률 ≥ 100% | `#2B8A3E` |
| 순조 | 진행률 ≥ 기대진행률 × 0.9 | `#1971C2` |
| 지연 | 0 ≤ 진행률 < 기대진행률 × 0.9 | `#E8590C` |
| 악화 | 진행률 < 0 (기준값보다 후퇴) | `#C92A2A` |
| 모니터링 | `targetValue` 없음 | `#868E96` |
| 자료없음 | 실적값 없음 | `#ADB5BD` |

- `statusOverride`가 유효한 값이면 자동 판정 대신 그것을 쓴다.
- 최신 데이터가 **3년(`STALE_YEARS`) 넘게** 갱신 안 됐으면 「자료 갱신 필요」 배지를 함께 표시한다.
  (상태 판정 자체는 바꾸지 않는다.)
- 색맹 대비로 상태 배지에는 색과 함께 **아이콘·텍스트를 병기**한다.

### 5.4 파생 값

- **추세**: 직전 연도 대비 변화량. `direction`을 반영해 개선/악화 방향으로 색을 정한다.
- **목표 평균 달성도**: 소속 지표 진행률의 평균 (자료없음·모니터링 제외).
- **숫자 표기**: 1000 이상은 소수점 없음, 100 이상은 1자리, 그 외 2자리. 천단위 콤마. `tabular-nums`.

## 6. 화면 요구사항

### 6.1 공통 레이아웃

- **화면 전체 폭 사용.** 최대폭(`max-w-7xl` 등) 제한을 두지 않고 좌우 여백만 준다.
- 개수가 유동적인 그리드는 고정 열이 아니라 `auto-fit`:
  - 목표 카드 `minmax(340px, 1fr)`
  - 지표 카드 `minmax(330px, 1fr)`
  - 집계 카드 `minmax(210px, 1fr)`
- 헤더 최상단에 **목표색이 가로로 흐르는 얇은 띠** (목표가 몇 개든 균등 분할).
- 헤더: 사이트명 + 부제 + 네비게이션 + 최종 갱신일 + 관리자 버튼 (sticky).
- 모바일 1열, 넓은 표는 가로 스크롤 컨테이너 안에.

### 6.2 `/` 통합 현황

전체 영역을 한 화면에서 비교한다.

1. **히어로** — 사이트 제목·부제 + 전체 평균 달성도 + 전체 지표 수, 상단에 영역색 띠
2. **전체 상태별 집계 카드**
3. **영역 카드** (영역당 1장) — 영역색 그라디언트 헤더 + 아이콘 + 도넛 평균 달성도 +
   목표/지표/이행과제 수 + 상태 스택바 + 소속 목표 목록. 클릭 시 `/[track]`으로 이동
4. **전 영역에서 관리가 필요한 지표** 8개 — 클릭 시 해당 영역의 지표 상세로 이동

### 6.2-1 `/[track]` 영역 개요

1. **히어로** — 목표색 띠 + 프레임워크명 + 사이트 제목·부제 + **전체 평균 달성도** + "지표 전체 보기" 버튼
2. **상태별 집계 카드** — 전체 지표 수(진한 카드) + 달성/순조/지연/… 각 카드에 개수·비율·미니 바
3. **목표 카드** (목표당 1장)
   - 목표색 그라디언트 헤더 + 큰 이모지 + 목표 번호·이름·설명
   - 도넛형 평균 달성도 링
   - 지표 수 / 세부목표 수
   - 상태별 스택 바 + 범례
   - 대표지표(`isHeadline`) 최대 2개와 각 달성률
   - **클릭 시 해당 목표로 필터된 지표 화면으로 이동**
4. **관리가 필요한 지표** (지연·악화, 진행률 낮은 순 5개) / **목표에 근접한 지표** (진행률 높은 순 5개)
   - **각 항목 클릭 시 `/indicators?indicator=<id>`로 이동해 해당 지표 상세가 바로 열려야 한다** (R24)
   - hover 시 밑줄 + 화살표 이동 피드백
5. **이행과제 요약** — 완료/추진중/지연/예정 카운트 카드

### 6.3 `/[track]/indicators` 지표

- **필터 바**
  - 목표 칩 (전체 + 목표별, 각 지표 수 표시, 활성 시 목표색 배경)
  - 상태 배지 칩 (해당 상태가 0건이면 숨김)
  - 검색어 (지표명·설명·세부목표·담당·출처 대상)
  - 정렬: 지표번호순 / 달성도 높은순 / 달성도 낮은순 / 최신 자료순
  - 카드↔목록 보기 전환
  - 필터 초기화
- **카드 그리드** — 세부목표별로 그룹핑하고 그룹 헤더에 목표색 세로선 + 코드 + 이름 + 지표 수
- **지표 카드 1장**
  - 좌측 4px 목표색 액센트 바, 아주 옅은 목표색 배경 tint
  - 지표번호 배지 + 목표명 + 상태 배지 (+ 임시저장 배지)
  - 지표명 (2줄 말줄임)
  - **최신값을 크게** + 단위 + 최신연도 + 전년 대비 증감 화살표 + 비고 + 「자료 갱신 필요」 배지
  - 미니 스파크라인 (목표색 그라디언트 area)
  - 진행률 바 (목표색 그라디언트 + 기대진행률 위치 눈금) + 기준값 → 달성 % → 목표값
  - 목표값이 없으면 진행률 바 대신 「모니터링 지표」 안내
- **목록 보기** — 지표 / 최신값 / 기준 / 목표 / 달성도 / 상태 표
- **상세 드로어** (우측 Sheet, 카드나 행 클릭 시)
  - 상단 목표색 띠, 지표번호·계층 경로·상태
  - 최신값 + 목표 대비 달성도 + 진행률 바 + 기대진행률 + 상태 설명
  - **시계열 차트** — 기준선(회색 점선, "기준 연도" 라벨), 목표선(녹색 점선, "목표 연도" 라벨),
    목표연도가 데이터보다 뒤면 X축을 목표연도까지 확장
  - 지표 설명 / 산출식 / 단위 / 방향 / 출처(+링크) / 갱신주기 / 담당 / 비고
  - 원자료 표 (최신 연도 먼저) + **해당 지표 CSV 내려받기** (BOM 포함, 엑셀 한글 안 깨짐)
- **`?goal=<id>`** → 해당 목표로 필터된 상태로 진입
- **`?indicator=<id>`** → 해당 지표 상세 드로어가 열린 상태로 진입

### 6.4 `/[track]/actions` 이행과제

이행과제가 0건인 영역은 **하위 메뉴에서 탭 자체가 빠진다**(환경상태·환경체감처럼 관측·조사만 하는 영역).
직접 주소로 들어오면 "등록된 이행과제가 없습니다" 안내를 보여준다.

- 상태별 집계 카드 4개 (클릭하면 그 상태로 필터, 활성 시 링 표시)
- 필터: 목표 / 기한 연도 / 검색어 / 초기화
- 목표별 그룹 → 아코디언 리스트
  - 접힘: 과제번호 + 상태 칩 + 기한 칩 + 세부목표 코드 + 과제명 + 요약 1줄
  - 펼침: 추진 경과 전문 + 담당 기관 + 최종 수정일 + 근거 링크 버튼들

### 6.5 `/[track]/data` 데이터·방법론

- 달성도 계산식 2개와 그 설명 (특히 "최신 데이터 연도 기준"인 이유)
- 상태 6종의 판정 조건 표
- 전체 지표 메타데이터 표 (번호·지표명·정의·단위·기준·최신·목표·출처·갱신주기·담당·상태)
- 전체 CSV 내려받기

### 6.6 관리자 (`/admin`, 로그인 필요)

## 7. 색상 시스템 요구사항

"전부 같은 색이라 멋없다"를 피하기 위해 **두 층으로 분리**한다.

### 7.1 목표색 (다양성 담당)

- 목표마다 고유색. 기본 예시: 13 기후 `#E8590C`(앰버) / 14 해양 `#0B7285`(딥 틸) / 15 육상 `#2F9E44`(포레스트)
- 색 **하나만** 지정하면 HSL로 분해해 다음을 자동 파생한다:
  `tint`(L 96.5%, 배경) / `border`(L 87%) / `text`(L 30%) / `deep`(L 32%, 그라디언트 끝) / 투명도 3단계
- 이 색이 **헤더 그라디언트 배너 / 카드 좌측 액센트 바 / 도넛 링 / 차트 라인·area / 아이콘 배경 /
  활성 필터 칩 / 진행률 바**에 전부 전파된다. → 목표 섹션마다 화면 인상이 확 달라진다.
- **색을 비우면** 10색 팔레트에서 순서대로 자동 배정 → 목표가 몇 개 늘어도 색이 겹치거나 비지 않는다.
- 팔레트: `#E8590C #0B7285 #2F9E44 #5F3DC4 #0B5394 #B02A37 #7048E8 #087F5B #D6336C #A9761A`

### 7.2 상태색 (일관성 담당)

5.3의 색을 전 화면에서 **동일한 의미로만** 쓴다. 절대 변주하지 않는다.

### 7.3 밋밋함을 깨는 장치

- 목표 카드: 그라디언트 헤더 + 큰 이모지 + 도넛 링
- 지표 카드: 좌측 액센트 바 + 옅은 배경 tint + 큰 숫자(tabular-nums)
- 차트/스파크라인: 목표색 그라디언트 area fill, 목표값은 점선 + 배지
- 진행률 바: 단색이 아닌 그라디언트 + 기대진행률 눈금 마커
- 카드 hover 시 살짝 떠오르는 그림자 + 이동

## 9. CSV 가져오기·내보내기 요구사항

- 대상 7종: `tracks` / `goals` / `targets` / `indicators` / `values` / `actions` / `config`
- **내려받은 CSV를 그대로 다시 올릴 수 있어야 한다** (왕복 가능한 형식).
- 엑셀 한글 깨짐 방지를 위해 내보낼 때 **UTF-8 BOM**을 붙인다.
- 올리기는 **파일 업로드**와 **표 붙여넣기** 둘 다 지원. 붙여넣기는 **탭 구분(TSV) 자동 감지**
  (구글시트·엑셀에서 복사하면 탭 구분이다).
- 첫 줄은 헤더. **컬럼 순서는 달라도 되고**(이름으로 찾음), 모르는 컬럼은 무시한다.
- 고유번호 기준 **upsert** — 있으면 수정, 없으면 추가.
- "기존 데이터를 모두 지우고 넣기" 옵션을 두되, 체크하면 **경고 배너**를 띄우고 백업을 권한다.
- 행 단위로 실패해도 전체를 중단하지 않고, **몇 행에서 왜 실패했는지** 메시지에 담는다.
  예: `3건 추가, 2건 수정, 1건 건너뜀 — 5행: 상위 목표 G99 를 찾을 수 없음`
- 전체를 처음부터 넣을 때의 순서를 화면에 안내: **영역 → 목표 → 세부목표 → 지표 → 실적값 → 이행과제 → 설정**
- 공개 화면의 영역별 내려받기를 위해 `?track=<코드>` 필터를 지원한다

## 10. 인증·권한 요구사항

- 공용 비밀번호 1개 (`.env`의 `ADMIN_PASSWORD`).
- 세션은 **HMAC-SHA256 서명 쿠키**. `httpOnly`, `sameSite=lax`, 운영에서 `secure`, **12시간** 만료.
- 비밀번호 비교는 **타이밍 안전 비교**(`timingSafeEqual`)를 쓴다.
- 비로그인으로 `/admin/*` 접근 시 `/login`으로 리다이렉트.
- **모든 쓰기 서버 액션은 첫 줄에서 `requireAdmin()`을 호출**한다. 화면 보호만으로는 부족하다.
- 로그아웃 → 쿠키 삭제 후 `/`로 이동.

## 11. 비기능 요구사항

### 11.1 성능

- 공개 화면 TTFB 100ms 이내 (SQLite + 인메모리 계산이면 충분).
- **운영 배포는 반드시 `npm run build && npm run start`.** dev 모드는 JS를 압축 없이 내보내
  청크 하나가 7MB를 넘고, 이것이 체감 느림의 대부분이다.
- **차트 라이브러리(recharts)는 지연 로딩**한다. 상세를 열기 전에는 필요 없으므로
  첫 로딩 번들에서 뺀다. (`next/dynamic`, `ssr: false`) → 지표 화면 259KB → 147KB
- **웹폰트 굵기는 실제로 쓰는 것만.** 한글 폰트는 굵기 하나당 유니코드 서브셋 파일이 124개 생긴다.
  Noto Sans KR는 400/500/700만 쓰고 `display: swap`으로 텍스트가 먼저 보이게 한다.

### 11.2 확장성

- 목표·세부목표·지표·연도·이행과제를 추가해도 **코드 수정 없이** 화면이 늘어나야 한다.
- 목표가 6~8개로 늘어도 레이아웃이 버텨야 한다 (auto-fit 그리드).

### 11.3 데이터 안전

- 삭제는 확인 후 실행하고, 하위 항목 개수를 미리 알린다.
- 시드 스크립트는 **기존 데이터를 모두 지우고** 다시 채우므로 그 사실을 문서에 명시한다.
- 실적값이 없다는 것과 값이 0이라는 것을 구분한다. **빈 칸으로 두고 0을 넣지 않는다.**

### 11.4 접근성

- 상태는 색만으로 구분하지 않고 아이콘·텍스트를 병기한다.
- 진행률 바에 `role="progressbar"`와 aria 속성.
- 아이콘 전용 버튼에 `aria-label` 또는 `sr-only` 텍스트.

## 13. 재구축 시 반드시 알아야 할 함정

> 실제로 부딪힌 것들. 모르면 똑같이 시간을 쓴다.

### 13.1 Node 18 + Tailwind v4 네이티브 모듈

`@tailwindcss/oxide`는 Node 20+를 요구한다. npm은 engines가 안 맞는 **optional 의존성을 조용히 건너뛰므로**
빌드 시 `Error: Cannot find native binding.`이 난다.
→ **Node 20 이상 권장.** Node 18을 써야 하면 `npm i @tailwindcss/oxide-<플랫폼>@4.3.3 --force --no-save`.
→ 플랫폼 전용 패키지를 `dependencies`에 넣으면 다른 OS에서 `npm install` 자체가 실패하므로
   반드시 `optionalDependencies`에 둔다.

### 13.2 shadcn CLI도 Node 20+

Node 18에서 `npx shadcn@latest init`이 `ReferenceError: File is not defined`로 죽는다.
→ `File`/`Blob`을 `node:buffer`에서 전역에 주입하는 preload 스크립트를 만들어
   `NODE_OPTIONS="--require ./polyfill.js"`로 우회할 수 있다.

### 13.3 dev 서버와 build 동시 실행 금지

둘 다 `.next`를 쓰기 때문에, dev 서버가 떠 있는 상태에서 `npm run build`를 하면
실행 중인 서버가 `MODULE_NOT_FOUND` / `Cannot read properties of undefined (reading '/_app')`로 깨진다.
→ 빌드 전에 dev 서버를 끄고, 깨졌으면 `rm -rf .next` 후 재시작.

### 13.4 Base UI Button의 `nativeButton`

shadcn v4는 Base UI 기반이라, `<Button render={<Link/>}>`처럼 **버튼이 아닌 것을 렌더하면 경고**한다.
→ 링크로 쓰는 Button에는 전부 **`nativeButton={false}`**를 붙인다.
   (진짜 제출 버튼에는 붙이면 안 된다.)

### 13.5 `useActionState` 서버 액션의 인자 순서

`useActionState`로 감싼 액션은 시그니처가 `(prevState, formData)`다.
JS 없이 순수 폼으로 POST하면 formData가 첫 번째 인자로 와서 `fd.get is not a function`이 난다.
→ 테스트할 때는 렌더된 폼의 `$ACTION_*` 히든 필드를 그대로 재전송해야 한다.

### 13.6 서버 → 클라이언트 props는 직렬화 가능해야

목표 색 톤 객체에 `alpha(a) => string` 같은 **함수를 넣으면 클라이언트 컴포넌트로 못 넘긴다.**
→ 미리 계산된 문자열(`a08`, `a15`, `a30`)로만 구성한다.

### 13.7 React SSR의 텍스트 주석

`{config.level1_label}별 현황` 같은 보간은 SSR HTML에서 `부문<!-- -->별 현황`으로 나온다.
→ HTML 문자열을 검사하는 테스트에서는 `<!-- -->`를 먼저 제거하고 비교한다.

### 13.8 페이지 파일의 named export 금지

App Router의 `page.tsx`에서 컴포넌트를 named export 하면 Next가 타입 검증에서 거부한다.
→ 공용 컴포넌트는 별도 파일로 뺀다.

### 13.9 Base UI 다이얼로그는 포털

`?indicator=<id>`로 드로어를 여는 경우, 서버 HTML에는 드로어 내용이 없고
**하이드레이션 직후 열린다.** 정상 동작이며, SSR HTML만 보고 실패로 판단하면 안 된다.

### 13.10 Prisma의 위험 명령 차단

`prisma db push --force-reset`은 AI 에이전트가 사용자 동의 없이 실행하지 못하도록 막혀 있다.
시드 스크립트가 스스로 전체 삭제 후 재주입하므로 `db:seed`만으로 충분하다.

## 14. 수용 기준 (테스트 체크리스트)

브라우저 없이도 확인 가능하도록, 렌더된 폼의 히든 필드를 재전송하는 방식으로 검증했다.
**아래 20개 항목이 모두 통과해야 완료로 본다.**

### 인증
1. 비로그인 `/admin` 접근 → `/login`으로 리다이렉트 (307)
2. 틀린 비밀번호 → 거부되고 세션 쿠키가 발급되지 않음
3. 올바른 비밀번호 → `httpOnly` 세션 쿠키 발급, `/admin` 200
4. 로그아웃 → 303, `Location: /`, 세션 쿠키 만료 처리

### 데이터 편집
5. 실적값 추가 → DB 반영
6. 최신값·달성률이 재계산됨 (예: 15-1-1 기준 16.9 → 2025년 18.4 입력 시 진행률 5% → 11%)
7. 실적값 추가 후 공개 지표 화면 정상 응답

### 확장성
8. 목표를 4번째로 추가 → DB 생성
9. 색을 지정하지 않으면 `color`가 비어 자동 배정 대상이 됨
10. 공개 개요에 새 목표 카드가 **코드 수정 없이** 노출
11. 목표 카드 개수가 자동으로 늘어남

### 임시저장
12. 지표 공개 토글 → `published=false`
13. 공개 대시보드에서 사라짐
14. 관리자 미리보기에는 보임
15. 미리보기에 「임시저장」 배지 표시

### CSV
16. 탭 구분 표 붙여넣기로 실적값 2건 일괄 반영

### 계획지표 전환 리허설
17. 설정에서 계층 명칭을 「부문/추진전략/계획지표」로 변경
18. 공개 개요 문구가 "부문별 현황"으로 바뀜
19. 지표 화면 제목이 "계획지표 현황"으로 바뀜

### 모니터링 영역
20. 통합 화면에 영역 3개 카드와 `/plan`·`/state`·`/perception` 링크가 모두 노출
21. 각 영역 화면에는 **자기 영역 지표만** 보인다 (환경상태에 온실가스 지표가 안 보여야 함)
22. 이행과제가 0건인 영역은 하위 메뉴에서 이행과제 탭이 빠진다
23. 이행과제가 있는 영역은 탭이 노출된다
24. 존재하지 않는 영역 주소는 404
25. `?track=<코드>` CSV 내보내기가 해당 영역 지표만 담는다

### 화면
26. 공개 화면(통합 1 + 영역 3 × 4) + 관리자 10개 화면 모두 200 응답, CSV 내보내기 동작

추가 수동 확인:
- 개요의 「관리가 필요한 지표」 항목 클릭 → 해당 지표 상세 드로어가 열린 채로 이동
- 목표 카드 클릭 → 해당 목표로 필터된 지표 화면
- 넓은 화면에서 카드가 좌우 여백 없이 꽉 차고, 빈 열이 생기지 않음
- 브라우저 콘솔에 Base UI 경고 없음
